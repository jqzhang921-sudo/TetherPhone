# TetherPhone 规划

> 记的是**为什么**，不是待办清单。跨会话接手时先看这份。
> 决定改了就改这里，别让代码和它分叉。

## 已经定死的

**平台：Next.js 网页。** 唯一理由是要发出去给 iPhone 的人用——Flutter 出 iOS 包
必须有 Mac、分发要 $99/年开发者账号，换 React Native / KMP 一样卡在同一处
（是苹果的规矩，不是框架的能力）。

**和 phone-ai-assistant 彻底分开。** 新东西、空数据、新人设。那边一个字节不动。

**代价：没有后台。** 它不会在你没打开的时候自己开口。主动说话那条线留在沐
（安卓）那边。网页版将来要，得做真后端（Web Push 订阅 + 定时任务 + 服务端调模型），
而且是反过来的：iOS 加到主屏幕后能收（走 APNs），国内安卓 Chrome 过 FCM 收不到。

**参照物是 `Vio9999/float`——壳可以抄，内核不能抄。** 它是角色卡 / 世界书那一脉，
中心是多角色扮演；我们的中心是关系和真实累积。抄它的内核会把 App 往扮演那边拽。

## 第 0 条：联系人是地基，不是功能

需求里几乎每条都带「双方」「每个人」——日记双方写、相册每个人保存、备忘录
每个人写、聊天有备注和主页。这些指的都是同一件事。

**联系人必须穿进每一张表**，哪怕 UI 上先只有一个。晚了就不是加字段，是把
日记 / 相册 / 备忘录 / 聊天 / 记忆全部改一遍取数逻辑。

推论：**人设、模型配置、记忆都挂在联系人下，不是全局设置**。全局只剩
API 凭据、壁纸、用户自己的资料。

## 三个和直觉相反的决定

**1. 「世界书」≠「人设」，不放同一个 app。**
人设是**常驻**系统提示词；世界书是**命中关键词才注入**。混在一起的典型症状是
「我明明写了它却不知道」——条目没被触发。
→ 先只做角色。世界书等人设真写不下了再说，很可能永远不需要。

**2. 记忆结构不重写，照搬 `MemoryTopic`。**
分类 + 名字 + 一行摘要 + 若干细节；**只有摘要常驻，细节靠工具取**——记得越多，
常驻成本几乎不涨，多数开源方案做不到这点。
实测数据：1856 条消息只沉淀 33 条记忆。**瓶颈是捕获率，不是结构也不是检索。**
换存储方案不会让它记得更多。
可视化（森林 / 星图）是**表现层，和结构解耦**。别让美化倒过来决定结构。
倾向森林：有生长感，且删除 = 落叶，不刺眼。星图适合展示关联，但记忆之间
目前没有关联数据，连线会是假的。

**3. 日记双方都能写——和沐那边相反，但这里对。**
沐那边不给用户写入口，因为价值在「这是它自己写的」。这里是**交换日记**：
各写各的，选择性给对方看，是另一个东西。
→ **「公开」这个动作本身要是内容。** 只做开关就没意思了；公开时在聊天里落一句
「我把三月七号那篇给你看了」，才有分量。几乎不要代码，但决定这功能是
「有个开关」还是「有件事发生过」。
→ **已定（2026-09-10）：它写的日记默认锁着，由它自己决定给不给你看。**
Cleo 否掉了「交换」（你开一篇它开一篇）——那是交易，不是给。
她的话是「模型自身不能把日记打开吗」，对的，所以做了工具：`open_diary`。
⚠️ 这条成立的前提是**它真的能开**。在有工具之前不能默认锁上——
锁了就永远打不开，那不是「它有秘密」，是「这功能坏了」。

## 工具：它的手（2026-09-10）

在这之前它只能说话，所有事都得人替它做。有了工具，「它自己决定把那一页翻开」
才成立。这也是后面记忆 / 朋友圈 / 备忘录它自己动的地基。

- 定义在 `lib/tools.ts`，聊天里跑一个**最多三轮**的循环（保险丝：模型偶尔会陷进
  「调用 → 看结果 → 再调用」的圈里，没上限就一直烧钱）
- ⚠️ **工具调用的参数是一片一片来的**，要按 `index` 拼。对每个 SSE 分片单独
  `JSON.parse` 必然失败，而症状是「工具从来不触发」，看不出是解析问题
- ⚠️ **注册了工具 ≠ 它会用。** 工具描述只回答「怎么用」，不回答「现在该不该用」
  ——什么时候该用必须另写一段规矩进系统提示词（`toolRules`）。
  这条在 phone-ai-assistant 里反复踩过
- 工具失败要把原话回给它（参数不是合法 JSON、id 不存在、那篇不归你开），
  **别静默失败**——静默失败会让它以为成功了

## 桌面（2026-09-10）

- **小组件**：时钟 / 天气 / 一起听 / 相册 / 备忘录。四列网格，宽的占四格、窄的占两格。
  长按桌面进编辑模式，「加组件」里勾。**卡片是入口不是装饰**，点了要能进对应的 app。
  - 一起听那张：**正在放就是「正在一起听」，没在放就是「一起听过几首」**
    ——同一张卡两种状态，不是两张卡
  - 天气缓存在模块里，十分钟内不重取。桌面每次重渲染都请求一次是在烧别人的接口
- **图标可拖动排序**。顺序存 `settings.appOrder`（逗号串，不是 JSON——settings 是
  扁平字符串表，塞 JSON 两头都要 try/catch）。⚠️ **registry 里新增的 app 自动补在
  后面**：加了新 app 不该因为老用户的顺序里没有它就消失。
  ⚠️ **`setPointerCapture` 会抛**（指针已抬起、或 pointerId 不是活跃指针时扔
  NotFoundError）。不接住的话整个 handler 断在那儿，`setDrag` 根本轮不到执行，
  症状是「按住拖不动，也不报错」。
- **自己传壁纸**。⚠️ **深浅从图里算，不让人选**——选错了整页字没法看，而且换一张
  还得再选一次。用封面取色那一套（WCAG 相对亮度 0.179）。
- **播放条能关掉**。暂停不等于关掉，一条永远杵在桌面上、没有出口的播放条就是个 bug。
- **便签显示是谁贴的**（头像 + 名字）。一块公用的板，只写「你写的」三个字，
  扫一眼分不出哪些是它留的。

## 硬约束（撞上之前就该知道）

| | |
|---|---|
| **iOS 七天清数据** | Safari 对网页写入的存储有上限：七天没打开就清掉。数据全在本地 = 全没。**加到主屏幕后不受限**——所以引导「添加到主屏幕」是必做的一步，不是锦上添花。**导出备份要早做**，兜最坏情况。 |
| ~~中文手写体 3–10MB~~ **已解决** | 用 Cleo 自己 App 里那份 **ZhiMangXing（钟齐志莽行书，SIL OFL，可商用）**，`tools/slice-font.py` 切成 unicode-range 分片自托管。**分层是关键**：按码位顺序均分是错的（常用字散落在整个区间，一页会打到二三十片，等于整包下载）；按 GB2312 区位分成 base / 一级 3755 字 / 二级 3036 字三层之后，实测一页只下 1.0MB、生僻那 1.1MB 一片不碰。不依赖 fonts.googleapis.com（国内不通）。「双方各有字体」= 再切一份，脚本现成。 |
| **相册装不进 localStorage** | 上限 5–10MB，一张手机照片吃掉大半，而且是同步 API 会卡界面。必须 IndexedDB。**趁数据还空的时候换。** |
| **定位要 HTTPS** | 局域网 http 页面拿不到地理位置（只有 localhost 例外）。天气要真实位置得先上 HTTPS，或退用 IP 定位（城市级，够用）。天气 API 用 open-meteo，免 key。 |
| **iPhone 上「你说它听」不行** | iOS Safari 的语音识别基本不可用；TTS（它说你听）可以。打电话功能在 iPhone 上是半残的。 |
| **`viewport-fit=cover` 必须配 `env(safe-area-inset-*)`** | 开了 cover，页面就伸进刘海和系统导航条的地盘（满屏的天空要的正是这个），但状态栏文字和底部 home 条必须自己让开，否则和真手机的导航条重叠。桌面上那台"手机"是浮在页面里的盒子、不该让边，所以插值只在 `max-width:480px` 的媒体查询里读真实值，外面固定 0。 |
| **安卓的返回键走浏览器历史** | 每打开一层（app / 资料卡）压一条历史，`popstate` 关最上面那层——系统返回键和界面里的 home 条汇成同一条路。iOS 加到主屏幕后**没有**系统返回键，所以 home 条不能撤，那边它是唯一出口。 |
| **「先占坑再干慢活」必须是原子的** | 结算类逻辑（打开信箱生成回信、打开动态生成评论）都是「挑一条 → 问模型几秒 → 写回」。挑和占**分成两个事务就有缝**：那几秒里另一个调用会挑中同一条，于是回两封信、评两次论。React 严格模式下开发时 effect 双跑能稳定复现。解法是 `idb.claim()`——读和写放进同一个 readwrite 事务，IndexedDB 会把同一张表上重叠的事务排队。⚠️ 事务里只能做 IDB 请求，await 别的 Promise 会让事务自动关闭。 |
| **低端安卓玻璃掉帧** | 同屏多块 backdrop-filter 有成本。降级方案：换成半透明实色。**等真机看到掉帧再做，别提前优化。** |
| **canvas 的三个坑**（天气那轮撞的，都不报错） | ① 渐变必须在 `translate/scale` **之后**建，否则渐变中心跟着变换又挪一次，圆里填的全是透明外圈——**画面整片空白**。② 量尺寸要用 `offsetWidth` 不能用 `getBoundingClientRect()`：rect 返回变换后的大小，而 app 打开动画起手是 `scale(0.16)`，画布会按 16% 建；ResizeObserver 只盯布局盒子、不管 transform，之后再也不会纠正。③ 图层顺序就是远近——云画在雨窗玻璃前面，就成了贴在玻璃上的一张纸。 |
| **玻璃通透度不能只调 alpha**（2026-09-10 做「再通透一点」时定的） | 把 alpha 一压，字会在**壁纸亮的地方**消失，而且只在特定壁纸上出——Cleo 在 Flutter 里踩过。所以做成两层：`--glass-alpha` 是想要的观感（已调到 46%/50%），`--glass-floor` 是这张壁纸算出来的**下限**，CSS 里 `max()` 取大。⚠️ **是下限不是设定值**：平坦壁纸算出来 20%，低于默认就什么都不改；只有真危险的图才顶上去（黑底一块高光 → 79%）。⚠️ 默认值只许存在于 globals.css 一处——所以用 CSS 的 `max()`，不是让 JS 去覆写 `--glass-alpha`；JS 里抄一份默认值，改 CSS 就会悄悄失效。 |
| **判可读性要看亮端和暗端，不是看「花不花」** | 亮度标准差量的是花不花，和能不能读是两回事：黑底壁纸上一块接近纯白的高光推不高标准差，却足以让一整行字消失。⚠️ 峰值取**第三亮**、谷值取**第三暗**，不是 p95/p05——32×32 的每个采样点已经是原图一整块的平均值，p95（1024 个里第 51 亮）够不着高光，算出来和不管亮端一模一样。⚠️ 取样要按 `background-size: cover` **裁过再取**：屏幕是竖的、图常是横的，整张图取样会让一块被裁掉、永远不显示的高光把玻璃顶厚，还查不出原因。 |
| **CSS 注释的两个坑**（同一晚踩了两次，都不报错） | ① **CSS 没有 `//` 行注释**，只有块注释。照着 .ts 的习惯写了三行 `///`，紧跟其后的 `.glass` 整条规则被吞掉，玻璃全变透明。② **块注释里不能出现 `*` 加 `/`**，哪怕包在反引号里当例子写——它会把注释提前闭合，后面同样烂掉。两次的症状都是「背景没了」，不亮红不报错，看起来像新语法不兼容——第一次差点顺着这个错方向去改写法。⚠️ 已实测：`max()` 在 `color-mix()` 里「字面量/变量」四种组合全都解析正常，别去绕开它。 |

## 顺序（按共用多少地基排，不按需求编号）

1. ~~**地基**~~ ✅ 联系人穿进所有表 + IndexedDB + 导出备份 + 聊天会话列表 + 资料卡
2. **内容三件套** —— 日记 ✅ / 信 ✅ / 相册 ✅。纸和手写体在 `lib/paper.ts` 共用
   - 日记 v1：双方能写、私密/公开、公开会在聊天里落一行事件、三种纹理 ×
     四种纸色、手写体、「让它写一篇」（显式触发，不是自动）
   - 信 v1：写了就寄（没有草稿态，攒着不发的信是备忘录不是信）、信封 + 封蜡、
     未拆状态（**封着时正文根本不进 DOM**，不是 CSS 藏起来）、拆信是个动作、
     桌面图标红点、「让它写一封」（显式，立刻）
   - **信不进实时对话的上下文**，公开的日记进。这条是从沐那边搬的：
     「信的价值有一半来自不在实时对话里」
   - **回信的延迟是在打开信箱时结算的。** 网页没有后台，所以「它在你不看的
     时候写了封信」只能在你回来时兑现——这不是妥协，信本来就该是
     「你回来的时候它在那儿」。延迟 25~100 分钟随机，固定值第三封就被认出来了
   - 相册 v1：聊天能发图（待发区可单张叉掉、选完就压到 1280 长边）、
     点开能「收进相册」、相册自己也能加图、日记能贴图（白边 + 微微歪）
   - **图只存一份**：photos 表存 Blob，消息和日记只存 id。同一张可能同时出现在
     聊天、相册、日记里，各存一份的话改一处得改三处、删一处剩两份孤儿
   - **发图时不猜模型能不能看图**：按 provider 名字猜能力是错的，会把图悄悄丢掉
     且查不出原因。原样按 OpenAI 多模态格式发过去，让上游报错——
     报错看得见，静默丢弃看不见
   - **没打字发图时不替她编一句「分析这张图片」**：那一句会让它去做图像分析，
     而不是像收到一张照片那样说话
   - 信也能装照片了（同一个 `PhotoPicker`）。两个都还欠**自动触发**
     （别做成排班表）和双方各一种字体（等第二份字体切出来）
3. **轻的** —— 备忘录 ✅ + 天气 ✅
   - 备忘录规矩一条没改地搬了沐那边的「小事」：**带勾选框、没勾的绝不自动消失、
     勾掉留一周可撤销**。「绝不自动消失」是关键——一条自己沉下去的待办，
     从人的角度和 bug 分不开
   - 板是**公用的**，它也能贴（`add_note`）和勾（`check_note`）。板上的内容进它的
     上下文，但 toolRules 里明写着**知道 ≠ 该开口提**：复述她自己写的待办就是催，
     一件事最多提一次而且要带来新东西
   - ⚠️ **别拿 `id.charCodeAt(0)` 当哈希**（挑纸色、歪几度这类）。id 开头是时间戳
     高位，同一天里根本不变——一板便签会全是同一个颜色，一篇日记里的照片会全歪
     同一个方向。用 `hashOf()`（FNV-1a，吃整串）
   - 天气 v1：真实定位（GPS → IP 三家兜底 → 手动改城市）、open-meteo 免 key、
     逐时 + 六天、七套 canvas 动画（晴昼的光/晴夜的星与流星/云随风飘/雾/
     雪分层/雨打湿屏幕/雷闪）。图标是手画的线稿，**不用 emoji**——emoji 的
     样子由系统决定，三个平台三个样，和界面永远不搭
   - 定位**明说是猜的**：实测同一个 IP 三家给的位置差七百公里，
     装作定准了比明说猜的更糟
4. ~~**记忆**~~ ✅ 结构照搬 `MemoryTopic`，表现层做了森林
   - 四类固定分类（她是谁 / 在意什么 / 我们之间 / 别这样对她），每类 5 个话题、
     每话题 12 条细节。**满了拒绝并列出现有的，不挤掉最旧的**
   - 四个工具：`remember` / `open_memory` / `update_memory` / `forget`
   - `update_memory` 的 `add_detail`（追加）和 `set_details`（整体替换）**互斥**。
     **刻意没有「删第 N 条」**——下标在模型手里必然出错，而且错了没声音
   - 排序按「分类 + 创建时间升序」，**不能按最近更新排**：摘要拼进 system 前缀，
     顺序一变整段重排，把历史挤出 KV 缓存
   - 记忆页两层，**刻意和模型看到的对齐**：默认只显示名字 + 摘要，点开才有细节
     ——你点开那一下，等于亲手做了一次 open_memory。还有个「原文」开关，
     直接看它每轮真正拿到的那段字（实测 7 个话题 13 条细节 = 242 字）
   - 树的形状由话题 id 决定，同一个话题每次看都是同一棵。**0 条细节就是光秃秃的**
   - ⚠️ 叶子不能按 tips 的原顺序挂：递归先左后右，前几个枝头全在同一侧，
     三片叶子会齐刷刷挤在左上角。先按 id 洗牌再取
5. **动态** ✅ —— 双方都能发、评论、回复评论、点赞
   - 它发有两条路：聊天里用 `post_moment` 工具自己发，或者「让它发一条」（显式）
   - 它回应你发的：**打开动态页时结算**。候选 = 「她发过、它还没回应过、且过了两分钟」
     ——**没有候选就连模型都不问**（频率由有没有事情发生决定，不由数字决定）。
     那两分钟只用来拦「刚发出去就秒评」，那种即时反应像机器人守在旁边
   - 它可以回「不说」，那也算一次回应（标记看过，不再问）——**别硬凑**
   - **动态不进实时对话的上下文**，和信同一条理由
   - 「人设」那个图标拿掉了：人设已经在联系人资料卡里能编辑，
     「同一个目的地两个入口只会让人多想一秒」

6. **音乐** ✅（客户端）—— 播放器在壳里、本地文件、可插拔音源
   - **播放器住在壳里不在音乐 app 里**：退出 app 歌要继续放。放在 app 组件里的话
     一关就卸载、audio 元素跟着没。桌面上有条小的显示在放什么
   - **音源可插拔**：留空只有本地文件；填一个 api-enhanced 兼容的地址就有在线搜索、
     播放、歌词。**服务不在这个 App 里，谁要在线音乐谁自己跑一个**——
     这样不用当那个运营方
   - ⚠️ **在线地址每次播放都现取，不缓存**：这类音源给的是带签名和有效期的临时地址，
     存下来隔天就是 403，症状是「这首歌突然不能放了」，看不出是过期
   - ⚠️ **`/api/music` 收前端传的 base 是个 SSRF 面**。自己用没事，部署出去就该用
     `MUSIC_API_BASE` 把地址钉死。内网地址在 production 下默认挡掉，
     **但开发时不能挡**——自己跑音源就在 127.0.0.1 上，一刀切会把主要用法堵死
   - 还欠：分享到聊天、「一起听」（要真后端）

## 音乐这条线查到的（2026-09-10）

- ⚠️ **`Binaryify/NeteaseCloudMusicApi`（★30k）已归档**，2024-02 最后一次推送。
  Float 依赖的就是它——照抄会抄到一个停维护的东西。
- 活着的是 **`NeteaseCloudMusicApiEnhanced/api-enhanced`**：★1.7k，2026-09 仍在推，
  MIT，有 npm 包 / Docker 镜像 / `vercel.json`。翻过它的 `util/request.js`，
  **确认支持 `realIP`**——海外部署被地区限制时传一个中国 IP 能绕过。
- 多平台的有 `ELDment/Meting-Fixed`（网易云 / QQ / 酷狗 / 酷我，PHP）。
- **「一起听」不用自己造同步**：网易云**自己就有原生「一起听」房间**，
  `zbqbbm/netease-listen-together-mcp` 是让 AI 进同一个房间选歌加歌。
  对 TetherPhone 的硬伤是它控制的是网易云官方客户端、声音从那边出来，
  网页播不了那个流；真做成的形态是「TetherPhone 里显示现在一起在听什么」。
- **实测结果（2026-09-10，Cleo 自己跑了一个 api-enhanced 实例）**：
  16 首样本里 `fee=8` 的 8 首**全部拿到完整音源 128kbps**，
  `fee=1` 的 8 首**全部只有 30 秒试听片段**，拿不到链接的 0 首。搜索和歌词完全可用。
  → **不登录能听的主要是翻唱和冷门**；正版热门基本只有试听。
  这不是 API 的限制是版权的限制——网易云 App 自己不登录也一样。
  搜「周杰伦 晴天」返回的全是翻唱，因为他的正版早就不在网易云了。
- **⚠️ 试听片段是有 url 的。** 只判断「有没有 url」会把 30 秒的试听当整首返回，
  播到一半突然没了、人不知道为什么。要把 `freeTrialInfo` 带到界面上说人话。
- **⚠️ `<audio>` 上千万别加 `crossOrigin`。** 加了才强制走 CORS，而音乐 CDN 不发
  `Access-Control-Allow-Origin`，整个加载被拦；症状是「点了没反应、时长 0、不报错」。
  普通播放本来就不需要 CORS，只有要读音频数据（Web Audio、画波形）才需要。
- **音源地址由服务端去请求**，所以填 `localhost:3300` 从手机上打开也是对的
  ——`localhost` 解析在服务器那台机器上，不是手机上。
- **⚠️ 浏览器直连 CDN 拿不到音频，真机复现了。**（我一开始以为是测试环境的限制，
  Cleo 在自己手机上试出同样的 `MEDIA_ELEMENT_ERROR` code 4「no supported sources」。）
  排除过的：换 https 一样、换 Referer / UA 一样、mp3 解码支持正常、
  同一个浏览器里公开 mp3 能放、服务端 fetch 同一个地址是 206 audio/mpeg。
  **原因没定位到，但结论是确定的：那个地址交给浏览器就是拿不到。**
- **解法：音频也经服务端转发**（`/api/music?op=stream`）。同源、不涉及 CORS 和
  混合内容、地址每次现取所以不会过期，还顺带能 seek（Range 原样透传）。
  实测整首 4:46 正常播，试听那首 30 秒也正常。**代价是音频流量走这台服务器。**
  ⚠️ Range 必须透传，否则拖不动进度条、长音频还要整首等下完。
- **登录（2026-09-10）**：VIP 完整版要登录自己的账号。登录做进了 App 里
  （设置 → 音乐账号），两条路针对不同处境：
  - **扫码**——手边有第二块屏时用（电脑上开页面，手机 App 扫）
  - **手机号 + 短信**——⚠️ **只有一台手机时唯一走得通的**：
    屏幕上的码没法用同一台手机去扫
  **登录态存 httpOnly cookie，不存 localStorage**——页面脚本读不到，
  也不会跟着「导出备份」跑进那个 JSON。登录后取音源自动升到 `exhigh`。
  ⚠️ 取音频字节时不带 cookie：那是 CDN 的地址，签名已在 url 里，发过去是白送凭据。
  ⚠️ 网易云返回的 cookie 一大串，只留 `MUSIC_U` / `__csrf` / `NMTID`，
  整串塞进浏览器 cookie 容易撞 4KB 上限。
  `MUSIC_COOKIE` 环境变量仍然支持，但**降级成兜底**：整站共用一个账号既是共享账号，
  也容易让号因为多地同时在线被风控。每个人自己的优先。
  ⚠️ **一句要说在前面的话**：谁在这个站上登录，就是把自己的网易云登录态交给这台
  服务器。
  → **已定（Cleo，2026-09-10）：别人不在她这登录，各自在自己设备上部署自己的。**
  音源本来就是可插拔的，这条路一直开着。

## 一起听（2026-09-10）

参照的是网易云自己那套「一起听」，但**只取主题、不取花哨**：Cleo 原话
「可以不这么花哨，突出主题就好」。所以唱片、转盘、距离、在线人数一概不做，
只留三样：

1. **两个头像并排** —— 陪伴感的全部来源是「有人和你在同一首歌里」
2. **一起听了多久** —— 累计秒数**挂在联系人身上**（是你和它之间的事，
   不是这台手机的属性）。计时在**播放器（壳）里**做，不在音乐 app 里：
   退出 app 歌还在放，计时也该还在走。按「真的在放」计，暂停就停
3. **换歌时它可能说一句** —— 它可以回「不说」，而且提示词写了这是常有的事：
   换一首就非要评一句，就成了每首歌都要交作业

## 「能不能让它真的感受到音乐」（Cleo 问的，2026-09-10）

**曲谱这条不走**：网易云接口不给曲谱；而且曲谱描述的是**作曲**，不是此刻在放的
这个录音——同一首歌现场版和录音室版差很远。

**走的是直接量声波**（`lib/music/analyze.ts`）：取前 75 秒解码成 PCM，量出
BPM（起拍强度自相关）、整体响度、起伏倍数、过零率（明暗）、六段响度曲线。
实测告五人《在这里等你》→ BPM 123、响度 0.47、起伏 3.8 倍、过零率 0.041。

⚠️ **能做成是因为音频改成经本站转发之后变成了同源。** 跨域读音频数据要 CORS，
音乐 CDN 不给——直连 CDN 的话这条路是死的。（那次「改用服务端转发」是被迫的，
结果顺带开了这扇门。）

⚠️ **不能拿单帧最大值给响度曲线做归一化。** 一个瞬态尖峰（一下鼓、一声齿音）
就能把其余段全压扁，然后看着像「中间突然变响」——那是瞬态不是结构。
按段平均值的最大值归一。同理 `describe` 只说**走向**（越往后越满 / 开头最满 /
中间最满），不说「第 N 秒变响了」——那种话很容易是瞬态造成的假象。

⚠️ **提示词里必须如实说这些是量出来的数、不是听觉。** 给了数据更要说清数据是
什么，否则它会顺着「你能感受音乐」演下去。实测它说的是「这首拍子挺快，后面又
收下去了」——对上了 BPM 123 和前半比后半满的曲线，而且**没有一句「我听到」**。

⚠️ `describe` **只描述量到的，不替它下结论**。写成「这首很悲伤」就是替它感受了，
而那正是它没有的部分。

代价：每首多下约 1.2MB 用于分析。

## 播放页（2026-09-10）

Cleo 要「做成播放器的样式」，参照网易云那张图，但**唱片、转盘、在线人数、距离都不做**
——她原话「可以不这么花哨，突出主题就好」。

- **两个头像在中间偏上**，一进来先看到「谁和你在这儿」，再看到在听什么
- **气泡两边都用毛玻璃**，只靠左右位置分谁说的（她说的：两个人都白色或都毛玻璃）
- **多出来的竖向空间给封面**，不要在封面和气泡之间留一块莫名其妙的空白
- **背景从封面取色**（`lib/music/tone.ts`），也能钉死成某张壁纸

⚠️ **取色的投票权重必须是 OKLab 的「彩度 × 明度」**，两个因子缺一不可。
这条是从 phone-ai-assistant 搬的，那边咬过两次：HSV 饱和度在接近黑的像素上
分母趋近 0、剧烈抖动（`RGB(10,8,12)` 肉眼纯黑，饱和度 0.33、色相 270°），
一张黑底封面八成面积的黑会把票全投给蓝紫；只用彩度也不行，一整片系统性偏冷的黑
仍然攒得够票，乘上明度才稳。深浅判断用 **WCAG 相对亮度 0.179**（白字黑字对比度
相等那点），不是 OKLab 的 L——两者不是一回事。

⚠️ **封面必须经本站转发**（`op=cover`）。不是为了 CORS 头，是为了**能读像素**：
跨域图画进 canvas 会污染画布，`getImageData` 直接抛 SecurityError。
转发时顺手让图床缩到 500×500——原图能到 1MB 以上，而这儿只要一张封面和
32×32 的采样。域名走白名单，别把这里变成通用图片代理。

**它说的那句在没人接之前不落库。** 听二十首歌就往聊天里灌二十条，那不是陪着是刷屏。
她回一句之后，这一来一回才一起写进对话——**有来有回的才留痕**。

**`play_song` 工具**：它也能给你放歌。挑歌时**优先挑能完整听的**——挑到只有
试听的等于没放，按下去 30 秒就断，那是添堵。工具规矩里另写了一条：
**别把放歌当回应用**——「她说累了就放首治愈的歌」是敷衍，想放该是因为想到了某一首。
- **充值没有别的渠道**：会员只能在网易云官方买。「解灰 / 换音源」那类绕过版权的
  做法不做。

Cleo 说：不用摆一排 emoji 让人挑，能从相册里选就好。

- **收成一个 `<Avatar face size ring />`。** 之前七个页面各写一遍圆角 span，

- ⚠️ **头像存的是裁好的小图本身，不是相册里那张的 id。** 这和
  `photos/store` 里「图只存一份、别处存 id」是反的，故意的：那条防的是同一张图
  散成三份改一处漏两处；头像是从原图裁出来的**另一张**图，而且要比来源活得久
  ——把那张照片从相册删掉，头像不该跟着变空白。
- 裁到 192 见方。不只是省空间：一条动态底下三十条评论就是三十个头像，
  拿 1280 的原图去画 20px 的圆，每个都要解码一次整张大图。上传的先压到 640
  再裁，别把三五兆的原图直接丢给 `createImageBitmap`。
- ⚠️ **用户头像的刷新走 `settings.userAvatarAt` 这个时间戳。** settings 本来就
  流到每个要画头像的组件，换头像时它一变，几处一起重读。不这么做就得单开一个
  全局 store，或者把 blob 顺着好几套 props 穿下去。（实测：在设置里去掉头像，
  不刷新，桌面组件立刻退回 emoji。）
- 备份**没动**：`backup.ts` 的 pack/unpack 递归走整棵树，新加 Blob 字段白捡。
- emoji 那排留着但设了图就收起来：新建联系人立刻有张脸，不用先去相册找图；
  设了图还显示就成摆设——点了没有任何反应。

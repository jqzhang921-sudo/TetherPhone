# TetherPhone 规划

> 记的是**为什么**，不是待办清单。跨会话接手时先看这份。
> 决定改了就改这里，别让代码和它分叉。

## 已经定死的

**平台：Next.js 网页。** 唯一理由是要发出去给 iPhone 的人用——Flutter 出 iOS 包
必须有 Mac、分发要 $99/年开发者账号，换 React Native / KMP 一样卡在同一处
（是苹果的规矩，不是框架的能力）。

**和 phone-ai-assistant 彻底分开。** 新东西、空数据、新人设。那边一个字节不动。

**代价：没有后台。** 它不会在你没打开的时候自己开口。主动说话那条线留在沐
（安卓）那边。网页版将来要，得做真后端（Web Push 订阅 + 定时任务 + 服务端调模型），
而且是反过来的：iOS 加到主屏幕后能收（走 APNs），国内安卓 Chrome 过 FCM 收不到。

**参照物是 `Vio9999/float`——壳可以抄，内核不能抄。** 它是角色卡 / 世界书那一脉，
中心是多角色扮演；我们的中心是关系和真实累积。抄它的内核会把 App 往扮演那边拽。

## 第 0 条：联系人是地基，不是功能

需求里几乎每条都带「双方」「每个人」——日记双方写、相册每个人保存、备忘录
每个人写、聊天有备注和主页。这些指的都是同一件事。

**联系人必须穿进每一张表**，哪怕 UI 上先只有一个。晚了就不是加字段，是把
日记 / 相册 / 备忘录 / 聊天 / 记忆全部改一遍取数逻辑。

推论：**人设、模型配置、记忆都挂在联系人下，不是全局设置**。全局只剩
API 凭据、壁纸、用户自己的资料。

## 三个和直觉相反的决定

**1. 「世界书」≠「人设」，不放同一个 app。**
人设是**常驻**系统提示词；世界书是**命中关键词才注入**。混在一起的典型症状是
「我明明写了它却不知道」——条目没被触发。
→ 先只做角色。世界书等人设真写不下了再说，很可能永远不需要。

**2. 记忆结构不重写，照搬 `MemoryTopic`。**
分类 + 名字 + 一行摘要 + 若干细节；**只有摘要常驻，细节靠工具取**——记得越多，
常驻成本几乎不涨，多数开源方案做不到这点。
实测数据：1856 条消息只沉淀 33 条记忆。**瓶颈是捕获率，不是结构也不是检索。**
换存储方案不会让它记得更多。
可视化（森林 / 星图）是**表现层，和结构解耦**。别让美化倒过来决定结构。
倾向森林：有生长感，且删除 = 落叶，不刺眼。星图适合展示关联，但记忆之间
目前没有关联数据，连线会是假的。

**3. 日记双方都能写——和沐那边相反，但这里对。**
沐那边不给用户写入口，因为价值在「这是它自己写的」。这里是**交换日记**：
各写各的，选择性给对方看，是另一个东西。
→ **「公开」这个动作本身要是内容。** 只做开关就没意思了；公开时在聊天里落一句
「我把三月七号那篇给你看了」，才有分量。几乎不要代码，但决定这功能是
「有个开关」还是「有件事发生过」。
→ 待定：它写的私密日记你看不到、但**知道它在那儿**（本子上一页锁着）。
很有力量，也可能让人一直惦记。**Cleo 未拍板。**

## 硬约束（撞上之前就该知道）

| | |
|---|---|
| **iOS 七天清数据** | Safari 对网页写入的存储有上限：七天没打开就清掉。数据全在本地 = 全没。**加到主屏幕后不受限**——所以引导「添加到主屏幕」是必做的一步，不是锦上添花。**导出备份要早做**，兜最坏情况。 |
| ~~中文手写体 3–10MB~~ **已解决** | 用 Cleo 自己 App 里那份 **ZhiMangXing（钟齐志莽行书，SIL OFL，可商用）**，`tools/slice-font.py` 切成 unicode-range 分片自托管。**分层是关键**：按码位顺序均分是错的（常用字散落在整个区间，一页会打到二三十片，等于整包下载）；按 GB2312 区位分成 base / 一级 3755 字 / 二级 3036 字三层之后，实测一页只下 1.0MB、生僻那 1.1MB 一片不碰。不依赖 fonts.googleapis.com（国内不通）。「双方各有字体」= 再切一份，脚本现成。 |
| **相册装不进 localStorage** | 上限 5–10MB，一张手机照片吃掉大半，而且是同步 API 会卡界面。必须 IndexedDB。**趁数据还空的时候换。** |
| **定位要 HTTPS** | 局域网 http 页面拿不到地理位置（只有 localhost 例外）。天气要真实位置得先上 HTTPS，或退用 IP 定位（城市级，够用）。天气 API 用 open-meteo，免 key。 |
| **iPhone 上「你说它听」不行** | iOS Safari 的语音识别基本不可用；TTS（它说你听）可以。打电话功能在 iPhone 上是半残的。 |
| **低端安卓玻璃掉帧** | 同屏多块 backdrop-filter 有成本。降级方案：换成半透明实色。**等真机看到掉帧再做，别提前优化。** |
| **canvas 的三个坑**（天气那轮撞的，都不报错） | ① 渐变必须在 `translate/scale` **之后**建，否则渐变中心跟着变换又挪一次，圆里填的全是透明外圈——**画面整片空白**。② 量尺寸要用 `offsetWidth` 不能用 `getBoundingClientRect()`：rect 返回变换后的大小，而 app 打开动画起手是 `scale(0.16)`，画布会按 16% 建；ResizeObserver 只盯布局盒子、不管 transform，之后再也不会纠正。③ 图层顺序就是远近——云画在雨窗玻璃前面，就成了贴在玻璃上的一张纸。 |

## 顺序（按共用多少地基排，不按需求编号）

1. ~~**地基**~~ ✅ 联系人穿进所有表 + IndexedDB + 导出备份 + 聊天会话列表 + 资料卡
2. **内容三件套** —— 日记 ✅ / 信 ✅ / 相册。纸和手写体已抽到 `lib/paper.ts` 共用
   - 日记 v1：双方能写、私密/公开、公开会在聊天里落一行事件、三种纹理 ×
     四种纸色、手写体、「让它写一篇」（显式触发，不是自动）
   - 信 v1：写了就寄（没有草稿态，攒着不发的信是备忘录不是信）、信封 + 封蜡、
     未拆状态（**封着时正文根本不进 DOM**，不是 CSS 藏起来）、拆信是个动作、
     桌面图标红点、「让它写一封」（显式，立刻）
   - **信不进实时对话的上下文**，公开的日记进。这条是从沐那边搬的：
     「信的价值有一半来自不在实时对话里」
   - **回信的延迟是在打开信箱时结算的。** 网页没有后台，所以「它在你不看的
     时候写了封信」只能在你回来时兑现——这不是妥协，信本来就该是
     「你回来的时候它在那儿」。延迟 25~100 分钟随机，固定值第三封就被认出来了
   - 两个都还欠：**贴图**（等相册）、**自动触发**（别做成排班表）、
     双方各用一种字体（等第二份字体切出来）
3. **轻的** —— 备忘录（搬沐那边「小事」的规矩：带勾选框、绝不自动消失、
   勾掉留一周可撤销）+ 天气 ✅
   - 天气 v1：真实定位（GPS → IP 三家兜底 → 手动改城市）、open-meteo 免 key、
     逐时 + 六天、七套 canvas 动画（晴昼的光/晴夜的星与流星/云随风飘/雾/
     雪分层/雨打湿屏幕/雷闪）。图标是手画的线稿，**不用 emoji**——emoji 的
     样子由系统决定，三个平台三个样，和界面永远不搭
   - 定位**明说是猜的**：实测同一个 IP 三家给的位置差七百公里，
     装作定准了比明说猜的更糟
4. **记忆** —— 结构照搬，表现层做森林
5. **重的** —— 音乐、打电话、驿站（MCP）

## 命名

**「信」不改叫邮箱/信箱。** 邮箱是装置名，让人想到通知邮件和垃圾邮件，是工具感；
「信」是慢的、有分量的。图标可以画成信箱。

## 待定

- 私密日记「你知道它在那儿」要不要做
- 音乐走哪条：用户自己传音频（轻）还是自部署曲库 API（重）
- 「一起听」是第一个真需要后端的功能——什么时候上后端 / 上不上账号
- 驿站（MCP）：浏览器开不了 stdio，只能连远程 HTTP 类型，且必须经服务端中转
  ——**别人填的 key 会过我们的服务器**。自己用是一回事，给陌生人用是另一回事。
  真做的话第一版建议只读、写操作默认关、并明说 key 经服务端。
